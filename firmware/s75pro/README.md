# S75 Pro 配套固件：F106

这是本分支为 **已核对的 AULA S75 Pro V1.03 硬件版本**制作的配套固件。它扩展硬件休眠，不改键盘的原生灯效渐灭算法。不是 AULA 官方固件，也不适用于同名型号的所有批次。

## F106 增加了什么

- **自定义硬件休眠**：1～120 分钟；App 退出后继续生效。
- **深睡**：保留厂商原始深睡路径，唤醒时可能有等待。
- **快速唤醒**：灯、屏关闭后保留蓝牙／2.4G 通信与按键扫描。
- **分阶段休眠**：例如最后一次按键后 3 分钟关灯屏、累计 5 分钟深睡；再次输入后重新计时。
- 保留原始断连超时和强制关机处理，保留原软件升级入口。

蓝牙不能直接配置这些选项。请在 USB 或 2.4G 下设置，再切回蓝牙使用。快速唤醒的实际电流和续航变化尚未测量。

## 在 App 内升级

1. 先保存 App 配置，并退出其他键盘驱动。App 备份只包含 App 已保存的内容，不能完整读回键盘原有素材和所有设置。
2. 使用数据线连接键盘并切到**有线**，保持稳定供电；升级只支持一把匹配的 S75 Pro。
3. 打开设备的 **“设备”页面 → 固件**，选择内置 F106，核对目标版本和文件指纹。
4. 点击开始并确认 App 提示，等待准备、擦除、写入、两次设备校验和重新连接完成。期间保持线缆连接。
5. 按 App 提示应用已保存配置；输入 `abc123`，确认没有缺字、连发，检查主灯、侧灯和时钟。

升级会重写键盘程序区。不能把恢复 App 配置等同于恢复全部屏幕素材或键盘原来的内容；屏幕上传图像也没有完整读回接口。USB 版本标识 F106 只表示版本字段；确认具体镜像需要结合文件 SHA-256 和写入后的设备校验。

## 升级中断与恢复

App 会暂停普通设备通信，让后台刷写过程独占键盘，保存失败阶段并阻止继续普通配置。重新打开 App 后按照恢复提示处理，可选择**上一版 F105**；这会失去分阶段休眠，保留深睡／快速唤醒选择。

恢复成功取决于键盘能否继续进入升级模式；拔线或强制结束后，不保证仅重新点击升级就一定恢复。请保留错误阶段、诊断包和具体 USB 设备状态。App 恢复确认后再检查输入和灯屏，不要只凭“设备重新出现”判定成功。

## 已完成的验证

- 两份镜像均在同一把 S75 Pro 上真实刷写；写入 4096 个 64 字节数据包，并分别校验程序和独立设备校验结果。
- F106 现有离线套件通过 1049 个 Cortex-M0 场景，包含分阶段时间线、实际按键重装计时、持久字段和原始深睡交接；另保留 1016 个原有深睡／快速唤醒场景回归。
- App 写入器测试覆盖相同镜像的 4096 个数据包与两次校验，升级管理测试覆盖失败阶段、重连检查和恢复状态。
- 蓝牙与 2.4G 的快速唤醒、深睡，以及 **3 分钟关灯屏／5 分钟深睡**均通过人工观察。快速阶段直接输入 `abc123` 完整、没有明显重连等待；深睡阶段出现原版唤醒等待，之后灯光和时间日期恢复。
- 已重新回刷本页 F106，恢复刷前配置，用户确认正常。未测量精确唤醒毫秒数、电流、长时间续航或所有 S75 Pro 批次。

## 复现补丁构建

本目录包含 F106 新增的 C 补丁和构建脚本。输入是仓库内已核验的 F105 二进制，**不是完整的厂商固件源码构建**。

```sh
python3 firmware/s75pro/build.py
```

需要 Python 3 和支持 `armv6m-none-eabi` 的 Clang。脚本在临时目录编译，核对原分支、可写空洞和保留区域，生成 `firmware/s75pro/build/S75Pro-F106.bin`，并要求与发布 F106 逐字节相同。工具链产生不同代码时脚本会拒绝结果；它不会自动接受新镜像，也不会访问或刷写键盘。

补丁入口：

| 原调用点 | F106 处理 |
| --- | --- |
| `0x77E` | 初始化休眠标记后继续原初始化 |
| `0x7C0`、`0x7C4`、`0x7C8` | 按暗屏状态处理主灯、侧灯和 LCD |
| `0x7DC` | 根据策略保留无线扫描，或交给原始 `0x194` 深睡 |
| `0x46D0` | 读出自定义／分阶段休眠时间并重装倒计时 |

补丁源文件：[connected-dark.c](connected-dark.c)、[custom-sleep.c](custom-sleep.c)。
